### 開工前要使用者決定的事

設計過程中發現幾處和現有規則衝突，或只能由使用者決定：

1. **A1 能不能用 Esc 回到牆面**：Claude Code 用 Esc 中斷 Agent，所以設計改成用 Ctrl+Shift+M 回牆面，Esc 照常送給終端機。
2. **A2 專注模式預設要不要靜音**：設計文件 4.1 規定「Agent 需要你時一定播放提示音」。設計提議專注模式預設只亮視窗邊緣（`focus_alerts`），視窗不在前景時照常出聲；要採用就得修改 4.1 的規則。
3. **T1 高對比主題與版面指定主題的優先順序**：terminals 版面檔寫死 graphite 主題；使用者選了高對比時，應該以哪個為準。
4. **T4 成套主題會改變既有外觀**：已升級的使用者切到 mac 版面時會換成建議的配色；要直接套用，還是只在設定頁提示。
5. **A4 要修改 host 與協定**：新增狀態歷史與 `session.timeline`；host 換版交接時要不要一起搬這些紀錄。

另外，A1 監看牆與 B1 復古終端機原本都提議 Ctrl+Shift+M，審稿時把 B1 的選單鍵改成 F10。

使用者的決定（2026-11-20）：1. 不用 Esc，Ctrl+Shift+M 回牆面（ADR-32）。2. `focus_alerts` 預設 `edge_sound`，亮邊緣並照樣播放提示音，4.1 的規則不變（ADR-32）。3. 隨 T1 延後，仍待決定。4. 建議主題只在設定頁提示，絕不自動改外觀（ADR-35）。5. 狀態歷史放在 host，換版交接不搬（ADR-33）。B1 的選單鍵用 F10（ADR-34）。下面提到的 `update_attention` 問題已在 A1 一併修正：「看過」改以畫面上實際畫出的終端機判斷（設計文件 4.1）。

設計時也發現一個現有的問題，與構想無關：`update_attention` 用目前的分頁判斷 Agent 是否「被看到」，不管畫面上實際畫了什麼。A1 的牆面會因此誤清「完成」標記；做 A1 時一併修正（見 A-usage-layouts.md）。

## 建議優先順序

| 順序 | 項目 | 理由 |
|---|---|---|
| 1 | Mission Control 監看牆（版面 A1） | 最貼近 AgentDesk 的用途：同時看很多個 Agent。現有版面都是一次看一個分頁，做不到一覽 |
| 2 | 高對比與色盲友善主題（主題 T1） | 工作量小；狀態目前主要靠紅綠區分，影響每個人能不能看清楚 |
| 3 | Focus 專注模式（版面 A2） | 做起來簡單，又是每天會用到的情境 |

## 一、依用途設計的版面

### A1. Mission Control（監看牆）

- 所有 Agent 排成格狀，每格是即時的小畫面：程式圖示、名稱、狀態，以及最後幾行輸出。
- 需要你的那格亮框，並排到最前面；完成的標上完成色。
- 點一格就放大成一般的終端機面板操作，再按一次或 Esc 回到牆面。
- 格子數依 Agent 數量自動調整，大約 2×2 到 4×3；太多時可以捲動，或只顯示需要你與工作中的。
- 適合同時跑 4～8 個 Agent。
- 要留意的地方：小畫面要用縮小的快照繪製，不能每格都開完整的 TerminalView，否則會拖慢效能；host 已經有快照，可以沿用。

### A2. Focus（專注模式）

- 只顯示一個終端機，其他介面全部隱藏。
- 底部一條細狀態列：其他 Agent 各用一個小點表示狀態。
- 有 Agent 需要你時，只在視窗邊緣輕輕亮一下，不跳通知、不出聲（可在設定調整）。
- 適合自己寫程式、偶爾看一下 Agent 的時候。
- 可以做成獨立版面，也可以做成任何版面都能切換的模式。

### A3. Review（審查台）

- 左邊是 Agent 的終端機，右邊固定顯示它改了哪些檔案與 diff，底部是 commit 按鈕。
- 對應 Agent 做完之後「看它改了什麼」這一步。
- 資料現有的 Changes 面板已經有，主要工作是重新排版，並讓 diff 跟著目前的 Agent 走。

### A4. Timeline（時間軸）

- 橫向時間軸，每個 Agent 一列，標出開始、工作中、卡住（需要你）、完成的時間段。
- 適合長時間的任務：離開一陣子回來，一眼看出剛才發生了什麼。
- 需要保存狀態變化的歷史；目前 agent_state 只記最新值與上一個值，要先在 host 端補紀錄（只記時間與狀態，不記內容）。

## 二、換外觀的風格版面

照 AgentDesk 98（已移除，ADR-28）與 AgentDesk Mac（ADR-31）的做法。原則相同：可以有那個風格，但不能照抄別人的素材，圖形、圖示、配色、字型都要自己做或使用授權允許的開源素材。

### B1. Terminal Classic（復古終端機）

- 仿老式綠色或琥珀色的映像管螢幕：掃描線、微微的螢光與暈開。
- 整個介面用字元畫出來：框線、選單、狀態都是文字。
- 終端機字型與配色跟著換成單色。

### B2. Tiling（平鋪式視窗管理器）

- 仿 Linux 平鋪式視窗管理器的風格：沒有裝飾、窗格之間留間距、頂端一條細狀態列。
- 以鍵盤操作為主：切換、移動、調整大小都有快捷鍵，滑鼠是輔助。

### B3. Cockpit（儀表板）

- 深色底加上螢光線條，Agent 狀態做成儀表：工作中的數量、需要你的數量、今天完成幾個。
- 像科幻片裡的控制台。實用性比較低，偏向好玩。

## 三、主題（配色）

### T1. 高對比與色盲友善

- 一套真正夠清楚的高對比配色（深、淺各一）。
- 色盲友善的狀態色，並且不只靠顏色：需要你、工作中、完成各有不同的形狀或圖示。
- 建議優先做。

### T2. 依時間自動切換

- 白天用淺色、晚上用深色，或跟著當地日出日落切換。
- 目前只能選淺色、深色或跟隨系統。

### T3. 跟著 Agent 狀態變色

- 主題的強調色依當下狀態微調，例如有 Agent 需要你時整體帶一點暖色。
- 要非常收斂，變化要慢、幅度要小，不然會干擾工作。

### T4. 成套主題

- 版面和主題成對設計，例如 AgentDesk Mac 配一套專屬的柔和配色。
- 目前每個版面已經各自記住一組深淺色主題（`layout_themes`），可以直接沿用。

### T5. 主題編輯器

- 在設定裡直接調整顏色，即時預覽，存成 `themes\` 裡的主題檔。
- 現在要自訂主題只能手改 JSON。

## 怎麼往下做

1. 使用者從上面挑一項。
2. 先做一頁設計草圖或截圖比較，確認方向。
3. 寫進設計文件（新的 ADR）與 PRD，再開發；完成後在 `sprint/current/status.md` 追加一列。

## 第二輪構想（2026-11-21）

使用者試用第一輪實作後的意見：後來實作的幾種版面還要再美化，而且很多版面不實用；要以「實用、好看又有趣」為目標重新想版面。以下是評估與提案，**尚未排入**，等使用者決定。

### 現有版面評估

| 版面 | 實用 | 好看 | 有趣 | 評估 | 提議 |
|---|---|---|---|---|---|
| AgentDesk（預設） | ★★★ | ★★ | ★ | 主力 | 保留 |
| Terminals | ★★★ | ★★ | ★ | 實用 | 保留，併入 Tiling 的直角與間距選項 |
| Mission Control | ★★ | ★ | ★★ | 方向對，但格子大半空白，只看得到最後幾行，資訊太少 | 由 Stage 取代 |
| Review | ★★★ | ★★ | ★ | 實用 | 保留，美化 |
| Focus（模式） | ★★★ | ★★ | ★ | 實用 | 保留 |
| AgentDesk Mac | ★ | ★★★ | ★★★ | 好看好玩，但視窗卡片與 Dock 佔空間 | 保留，定位為好玩的外觀 |
| Tiling | ★ | ★ | ★ | 跟 Terminals 幾乎一樣，只差直角與間距 | 併進 Terminals 成為選項 |
| Cockpit | ★ | ★★ | ★★ | 儀表多半顯示 0，佔三分之一畫面，終端機被擠窄 | 拿掉，由 Stage 與 Inbox 取代 |
| Classic | ★ | ★★ | ★★★ | 純好玩，單色讓 diff 看不出顏色 | 保留當彩蛋，不列在主要清單 |

### 新版面構想

**C1. Inbox（Agent 收件匣）**：建議最先做。

- 把需要你處理的事排成一列卡片，像信箱：每張卡片寫 Agent 問了什麼、改了哪些檔案、等了多久。
- 卡片上直接有「同意」「拒絕」與回覆輸入框。Claude Code 要你核准權限或回答問題時，不用切過去就能處理。
- 處理完的卡片滑走；清空時出現小小的「Inbox zero」畫面。
- 實用在哪：同時跑多個 Agent 時，真正花你時間的是「誰在等我、要我做什麼」。
- 待確認：卡片上的「問了什麼」從哪裡來。依 ADR-09 不從畫面文字推斷狀態，所以問題內容要用 OSC 7501 的訊息欄位或 hook 回報；畫面最後幾行只能當參考顯示，不能拿來判斷狀態。「同意／拒絕」實際送出的按鍵要依各 Agent CLI 的提示格式確認。

**C2. Stage（主舞台）**：取代 Mission Control 與 Cockpit。

- 一個大的主畫面，加上底部一排即時縮圖，像視訊會議的排版。
- 縮圖是每個 Agent 的小畫面；有 Agent 需要你時，它的縮圖亮起並排到前面，點一下就和主畫面交換。
- 比監看牆實用：永遠有一個能好好操作的大畫面，同時看得到全部。
- 可沿用 Mission Control 的 `screen_tail` 快取與排序（`wall_order`）。

**C3. Pair（並排比較）**

- 兩個 Agent 左右並排，下方一個共用輸入列，可以把同一個任務同時送給兩邊（例如 Claude Code 與 Codex）。
- 兩邊都完成後，中間顯示誰先完成、各改了幾個檔案。
- 有比賽的樂趣，也真的能拿來挑比較好的結果。
- 待確認：同一個任務送兩邊時，兩個 Agent 最好在不同的 worktree，避免改同一份檔案；可以搭配現有的 worktree 功能。

**C4. Garden（Agent 小花園）**：純好玩，但也有用。

- 每個 Agent 是一隻自己畫的小動物：工作中在跑、閒置時睡覺、需要你時揮手、完成時開心跳一下。
- 適合開在第二台螢幕，當成用餘光就看得懂的狀態顯示。
- 動畫要遵守 Windows 的「減少動畫」設定，視窗不在前景時降低更新頻率。

### 美化：所有版面一起整理

後來加的版面由不同的 agent 分頭實作，風格不一致。先定一套共用的設計規則，再全部套用：

- 間距與字級：統一的 4／8 px 間距系統，標題、內文、說明三層字級。
- 狀態動畫：狀態改變時淡入淡出或輕微位移，不突然跳色；遵守「減少動畫」設定。
- 空白狀態：簡單的插圖加一句話，取代現在空白的卡片。
- 質感：卡片加細微陰影與邊緣高光，選取狀態更明顯。

### 建議順序

1. 美化與收斂：先定共用設計規則；Tiling 併進 Terminals；拿掉 Cockpit；Classic 改為彩蛋。
2. Inbox（C1）：實用價值最高。
3. Stage（C2）：取代 Mission Control。
4. Pair（C3）與 Garden（C4）視使用者興趣再做。

### 待使用者決定

- 是否拿掉 Cockpit、合併 Tiling、把 Classic 改為彩蛋。這三個都是第一輪才依使用者要求做的，要使用者同意才動。
- 是否用 Stage 取代 Mission Control，或兩者並存。
- C1～C4 要做哪幾項、順序為何。
